# 2026-8-3 11:45

V-IDS AI/Data 파트 개발 요약

모델은 CAN 프레임 32개를 하나의 윈도우로 묶어서 보는 autoencoder 기반 이상탐지 모델
autoencoder_v5 모델을 만들었음.
정상패턴을 학습해서 정상과 다르게 재구성되는 윈도우를 공격으로 판정하는 방식

구조는 Dense 354 -> 64 -> 16 -> 64 -> 354
판정방식은 두 종류 오차
1. 354차원 평균 오차
2. 마지막 2차원만의 오차
를 따로 계산해서 둘 중 하나라도 임계값(기준점)을 넘으면 공격으로 판정


그리고 MCU 이식은 개발 간 2번 변경사항이 생김
1. 처음엔 ST공식도구인 X-CUBE-AI 로 자동변환하려 했지만, 현재 구매된 NUCLEO-F103RB(Cortex-M3) 을 지원하지 않는다는 것을 알게됨.
그로인해 모델크기가 작아서 직접 C로 순전파를 구현하는 쪽으로 전환함
2. float32로 가중치를 그대로 저장하게될 시 187KB로 우리 MCU flash(128kb)를 초과한다는 걸 발견함
그로인해 가중치만 int8로 압축하고 계산은 다시 float32로 유지하는 방식으로 해결함
성능저하의 걱정이 있었으나 검증결과 거의없다고 판단

임베디드 파트가 사용할 인공지능 파일들은
** ai/export/ ** 폴더에 있는 파일들임
1. feature_extract.h 와 feature_extract.c -> CAN 프레임을 32개씩 모아 354차원 벡터로 변환하는 역할을 함
2. inference.h 와 inference.c -> 그 벡터를 받아서 공격 여부를 판단하는 역할
3. autoencoder_v5_weights_int8.h -> 학습된 가중치 (양자화 처리됨), autoencoder_v5_weights.h 파일은 이전 초과된 헤더파일로 신경안써도됨

연결방법은 딱 두 줄임
if (feature_extract_push(&frame, buf)) { //32프레임 다 모이면 1 반환 
    vids_result_t result = vids_detect(buf); //VIDS_ATTACK /VIDS_NORMAL }

내부에 뭐가 들었는지 (모델구조, 특성계산방식)은 몰라도되고, 이 두 함수 시그니처만 알면 CAN 수신 로직과 OLED/부저 알림 사이에 끼워넣기만 하면됨

최종 검증사항
1. flash는 48.7kb, ram은 11.4kb로 보드 예산인 128kb와 20kb 안으로 들어옴
2. 로컬 gcc로 문법 컴파일 확인 + 기능테스트 통과
3. 우리가 해야할 과제는 실제 STM32CubeIDE/ARM toolchain으로 빌드해봐야함. 실제 프로젝트에 넣고 처음 빌드할 때 확인 필요
